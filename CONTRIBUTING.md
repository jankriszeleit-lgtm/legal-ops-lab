# Contributing

Contributions are welcome where they improve the public Legal Ops material in this repository.

## Good contributions

Examples:

- identifying an unclear instruction;
- proposing a simpler workflow;
- adding a reproducible test case;
- improving installation portability;
- documenting a failure mode;
- contributing a public evaluation;
- improving examples without adding confidential information.

## Please do not contribute

- client or matter data;
- privileged or confidential information;
- credentials or secrets;
- proprietary third-party content;
- material copied from a private repository unless you have the right to publish it;
- claims presented as empirical results without the underlying test or evidence.

## Pull requests

Keep pull requests focused.

A useful pull request should normally explain:

1. what problem it addresses;
2. what changed;
3. how the change was tested or reviewed;
4. whether it changes behaviour, only documentation, or both.

By contributing material that you own, you agree that it may be distributed under the license applicable to the part of the repository to which you contribute.

## Evaluation contributions

For evaluations, prefer:

- reproducible inputs;
- explicit expected behaviour;
- observed behaviour;
- version or release tested;
- clear PASS / FAIL / UNVERIFIED criteria;
- no reconstructed or invented evidence.

## Maintainer discretion

Opening an issue or pull request does not create any obligation to merge, respond within a particular period, or support a proposed use case.
